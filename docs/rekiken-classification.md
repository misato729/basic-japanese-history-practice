# 歴検型5セットの章節・文化史分類

2026-11-06の追加依頼により、模試2・4・6・8・10の全250問に章節を設定した。保存先は本サービス専用のローカルDB。模試単位に加え、ホームの「条件を指定」から章節・文化史で絞って演習できる。

## 分類基準と結果

分類の正本 `config/exam.json` に合わせ、各問の主に問う知識を読み、主分類を一つずつ設定した。直接比較する別節の知識がある6問には関連節を付けた。共通本文の背景、誤肢や解説だけへの登場は、関連節を追加する理由にしていない。

文化史は47問。内訳は美術史12問、音楽史5問、文学史5問、その他の文化史25問で、一問に複数の内訳を付けていない。国史編纂・地誌や総合芸能は「その他」にそろえ、芸術・学問そのものを問わない開催年の対応などは、文化史へ機械的に含めなかった。各模試が四つの内訳すべてを含むという意味ではない。

問題・主知識・正答内容と既存の原典照合記録を全250問確認し、別担当も候補の結論を見る前に判定を固定して比較した。節の境界が曖昧な箇所は原典画像の本文・図・次節見出しで確認し、主分類2件と関連節2件を修正した。文化史内訳の境界も調整し、最終対応表と実行入力の一致を独立に確認した。問題・正答・解説の歴史的内容は変更していない。

## 保存と保全

共通Writerと単一トランザクションで250問の分類だけを更新した。保存後の全件再読込に一致し、反復は変更0件。問題ID・選択肢ID・本文・正答・解説・配点・根拠資料・大問所属・公開状態・内容版・回答履歴・お気に入りを保持した。対象外教材と利用者等の件数・行digestも、各更新の前後で一致した。画面/API操作で変わる利用制限カウンタまで全期間不変とは主張しない。

初回の保存検査では、既存Writerが同じ共通本文参照も削除・再作成するため参照行IDが変わることを検出し、トランザクションが取り消された。同一参照なら参照行を再作成しない修正を行い、参照行IDまで保持して最終保存した。失敗した実行記録を消して成功扱いにはしていない。

## 検証

- 独立した末尾 `_test` のDBと合成データによる分類・大問・回答の回帰検査23件が成功。追加検査は参照行ID、保存済み回答、お気に入り、選択肢、内容版と反復を確認する。
- Writerの独立レビューと比較ガードの合成9例が成功。新規参照や参照変更には従来の更新処理が働く。
- 型検査が成功。
- 実APIで章・節・文化史の106条件と全250問の分類表示を照合。章節とのAND、文化内訳のOR、関連節による取得、0件時の404、回答前の正答・解説・出典の非露出を確認した。
- PCで章節＋美術史を指定して開始・回答・次問移動、390pxのスマートフォンで分類表示と音楽史＋文学史の複数選択を操作した。絞込条件が次問へ保たれ、観察した画面の横はみ出しはない。実教材の操作は匿名で行った。模試10で音楽史だけを選んだ0件の条件も実画面で確認し、条件外の問題へ進まない。

今回、新しい問題や分類区分は作成せず、本番DB・リモートへの送信、commit、push、デプロイは行っていない。
